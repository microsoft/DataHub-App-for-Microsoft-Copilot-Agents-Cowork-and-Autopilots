DataHub App / Reading guide

How to read the DataHub App

Use the signals. Question the estimates.

Observed
Users, prompts, sessions and credits count what the loaded sources record. They are not a complete census of all AI use.
Inferred
Task categories, fit grades and readiness use rules over metadata. They suggest where to look, not what someone achieved.
Modelled
Expert-equivalent hours and value estimate work at assumed task times and an hourly rate. They are not measured time saved, cash savings or realised productivity.

Before comparing numbers

Check dates, filters and source labels. Dates are UTC. A source's freshness date is its newest row, not today's refresh time; it ignores page filters and does not prove every intervening day loaded.

Open each page's tabs. The bar offers dates, org, licence, Activity (Copilot chat, Agents, Cowork) and agent filters where applicable. Read Not filtered by notes. Group by changes the org attribute; missing org matches can leave people out of breakdowns.

Blank, hidden, not connected or failed to load does not mean zero. Purview is not the authoritative Copilot usage report; its coverage can differ from the Microsoft 365 admin center and Viva Insights.

Pages 2-9: full-app tour. Pages 10-16: visual metric explainers for Value, Consumption, Efficiency and Readiness. All worked examples are fictional arithmetic, not app results or benchmarks.

02 / Work and value

Value

What work is recorded, and what might it be worth?

Task breakdown
Tasks are prompt-resource rows, not completed outputs. One prompt touching three files can count as three tasks. Prompts are distinct messages; sessions group a user, app and thread. Scheduled Cowork runs can make an owner active without adding prompts or sessions.
Estimated value
Copilot and agent hours use behaviour-specific units, assumed minutes and adjustments. Value = expert-equivalent hours x hourly rate. Conservative, Typical and Optimistic pick the low, middle and high effort bands. Cowork uses separate task-category time bands.
Value by habit
Last full month's hours per person by habit, plus concentration among the busiest people. Groups below five people are suppressed. More activity gives more work to count; this is not evidence that habit caused value.
Cost vs value
Return on cost = estimated value / counted cost. Below 1x, cost exceeds that scenario's value. Break-even hourly rate is the rate that would make them equal.

Read the cost basis

Dates and org narrow value and licence cost. Costs that cannot follow the org selection are left out, not apportioned; read the filtering notes. Shared activity/credit dates are used when available. Licence cost uses the licence snapshot, monthly price and days / 30.44.

Check Prices, exchange rate and credit coverage. Missing credits leave licence-only cost and can overstate return. Free unlicensed chat, Azure AI Foundry work and GitHub Copilot are outside the comparison.

Agent cost is allocated by credit share and matched to activity by name, not a dated per-agent invoice. Agents' value can include licence-funded agents, so that pairing may read high. Annualised value is an extrapolation, not a forecast.

03 / Credits and cost

Consumption

Read quantity, price and coverage separately.

All products
Compare the same dates. Credit costs are in US dollars; Azure stays in its billing currency. Do not add unlike currencies. This optional page needs Consumption Central.
Budget runway
Spend to the newest data date, projected in a straight line to month end. It uses the latest loaded month, not necessarily today. Weekly Cowork cost is spread over seven days. It ignores seasonality, pack exhaustion and future price changes.
Cowork / Work IQ
Weekly credits by group or person. The selected period uses Capacity Pack credits first at the prepaid rate, then pay-as-you-go. Blank or zero limits mean no limit set, not zero allowance.
Copilot Studio
Read credits by agent, model, feature and user alongside the source note. Agent/user costs use pay-as-you-go rates; they need not reconcile to a tenant total with a prepaid split. Concentration describes who uses credits, not who creates value.
Azure
Solution and Foundry spend, trends, services, models and resources come from cost exports. Read the cost basis and billing currency. Resource inventory is not evidence of spend.

Not every cost is an invoice

Credit cost is calculated from recorded credits and Rates & packs. Azure cost comes from the billing export. Budgets are optional comparison limits.

Studio exports take precedence over API coverage. The API sees only environments with allocated credits; a user-only roll-up misses unattributed credits. Missing feature/model detail is not zero use. Cowork is weekly; exports and billing can lag.

04 / Fit and next steps

Efficiency
and Readiness

Find candidates for a closer look, not automatic decisions.

Efficiency

Cowork fit
Grades the session's recorded work: Strong fit spans apps, builds a file or draws on many sources; Fair fit has some sources or one-app work; Worth a look is chat-only. Too light to grade is excluded from shares.
Model fit
Compares work weight with the dearest logged model tier. Frontier on light work suggests a lighter model; Workhorse on strong-fit work suggests trying stronger. Missing models are not judged; a segment needs five judged sessions for a verdict.

Readiness

License readiness
Prioritises unlicensed Copilot users by task intensity and active days; Microsoft 365 workload breadth contributes when available. Check weeks of evidence and roster matching. Dormant seats are inactive for 30+ days before the newest audit date, not necessarily today.
Heavy users without a licence
Last full month's habit bands split by licence. Shares need at least five people. This identifies demand; it does not predict what buying a licence would change.
Cowork readiness
Ranks Copilot users yet to try Cowork by breadth of app use, prompts per session and agent use. Equal depth leaves breadth and agent use to separate candidates.

Grades read metadata, not prompt or answer quality. There are no per-call token costs here. Fit and readiness thresholds are design choices; licence status is a snapshot, not historical entitlement. Do not treat rankings as employee performance assessments.

05 / People and working context

Leaderboards
and Work patterns

Understand concentration and context, not individual worth.

Leaderboards

Leaderboard
People ranked by sessions under the page filters, with their task mix. Concentration shows the top 1%, 5% and 25% shares; a slice needs five people. Security Copilot automated sessions are excluded.
Agents
Users, sessions and spread across functions and organisations show reach. Registry descriptions and lifecycle add context when loaded. No matched usage can mean an identifier/coverage gap, not an unused agent.

Work patterns

Microsoft 365 activity
People active, workload reach, meetings, emails and calls. Weekly rates use loaded days, not missing days counted as zero.
Apps and devices
App reach, apps used and platform reach. A person can use several platforms, so shares can overlap. No app use reported means no apps-report entry, not no Microsoft 365 activity.
Copilot in the flow of work
Copilot reach and licensed people not using it, plus comparisons with other Microsoft 365 users. A ratio above 1x means more recorded activity per person, not a causal productivity gain.

Work patterns is optional. Microsoft 365 reports arrive about 2-3 days late; history builds from available reports. Concealed names prevent org, licence and Copilot matching. Small organisations are pooled as Smaller groups.

Open Show lists for detail. Person and registry lists return at most 1,000 rows; grid sorting/searching acts on those rows. Use page filters to change the underlying selection.

06 / Quality signals

Agent Evaluation
and Feedback

Start with outcomes; check the denominator.

Agent Evaluation

Performance
Conversations, resolution, failure, abandonment, errors, hand-offs and satisfaction. Resolved is the agent-resolved share of all conversations; true failure uses conversations that actually started. Implied success is an orchestration signal, not a user's rating.
Conversations & topics
Inspect themes and topic health, answer archetypes, knowledge sources and gaps. Grounded means an internal source was used, not that the answer was correct. Friction runs from 0 to 100; higher is worse.

Use this page's Date, Department and Agent choices alongside applicable top-bar filters. CSAT is thumbs up / (up + down), per turn; sparse feedback is not representative of everyone. Response time is a latency signal, not time saved. Hours lost is an estimate.

Feedback

Reads the optional Microsoft 365 product feedback export: trend, theme/category, surface or agent and comments. Satisfaction is thumbs up / all feedback items, so it is not the same denominator as Agent Evaluation CSAT.

Date and agent filters apply; organisation and licence do not. Categories use English keyword rules and can misclassify comments. More complaints may reflect more use or a change in response volume.

Agent Evaluation needs its own model from Copilot Studio transcripts. The app shows aggregates and feedback comments, not full conversations. Feedback comments can still be sensitive; share exports only with authorised readers. Neither source proves answer quality across all use.

Do not compare unlike satisfaction measures07 / 09

07 / Ownership and exposure

Governance

A review queue, not a compliance verdict.

Estate health
Agent inventory, lifecycle and review flags. Governance reviews tenant-built, unblocked agents; catalogue listings are not the same population.
Exposure
Compare sharing scope, declared data access and sign-in requirement. Org-wide access to org content deserves review; it is not evidence that data was leaked.
Accountability
Check owners and account state at the last load. Disabled, not found, absent and not checked mean different things. Not found can also mean the recorded owner ID is not a user account.
Review queue
Flags include departed/missing owners, org-wide org data, shared agents with no recorded use and no sign-in requirement. Weighted flags order the queue; they do not measure actual harm.
Shadow AI
Defender observations distinguish tools run, domains reached, software installed and Cloud Discovery. Device and people counts are different units. Cloud Discovery people cannot be added across apps.

Know which estate you are seeing

With Agent 365, the page reads the registry. Without it, Azure Resource Graph can provide Copilot Studio agents only, at the latest load. Read the coverage note above each tab.

These are snapshots, not historical views; date and org filters do not narrow them. Agent filters apply where supported. Shadow AI does not follow the page filters.

Registry details can be up to a week old. Sign-in settings are reported configuration, not a test. Defender covers only onboarded devices, watched tools and available feeds: a floor, not a census. Missing data must not be read as a clean bill of health.

Metric explainer / Value

From recorded work
to estimated hours

More rows do not necessarily mean more finished work.

Copilot / agent hours = sum of
effort units x scenario minutes x category adjustment / 60

Per-turn behaviours use distinct prompt IDs. Per-resource behaviours use prompt-resource rows divided by that behaviour's estate-wide rows-per-prompt average. This normalises the resource mix; it is not raw files x minutes.

Illustrative example / assumed band, not a shipped task default

100 per-turn units at 6 / 12 / 18 minutes, adjustment 1, give 10 / 20 / 30 hours. At $50/hour and penalty factor 1, value is $500 / $1,000 / $1,500. Changing the hourly rate changes money, not hours.

Cowork uses a different calculation

It sums thread + task-category groups: inferred runs x category minutes x adjustment / 60. Analysis/research uses material rows / 5; email and communication / 4; meetings / 3; code / 6. Runs round to nearest (ties to even), minimum one; other categories use one run.

For example, 10 qualifying material rows in one Analysis & Research group imply 2 runs. Its shipped Typical band is 67 minutes: 2 x 67 / 60 = 2.23 hours at adjustment 1. This is inferred effort, not a stopwatch measurement. Assumptions edits behaviour times, not Cowork's category bands.

Scope: page filters, chosen scenario and shared task-time settings

Metric explainer / Value

Return on cost
and break-even rate

Illustrative example / US dollars, one common 30-day span

10 licensed seats at $30/month cost 10 x $30 x 30 / 30.4375 = $295.69. Add $100 of counted credits: total $395.69. Suppose the paired value is $500 / $1,000 / $1,500.

Return on cost = value / counted cost
Typical: $1,000 / $395.69 = 2.53x
Break-even: $50 / return = about $19.78/hour (unrounded ratio)

Below 1x, cost exceeds the chosen scenario's value. A high ratio may reflect generous minutes/rates or missing costs, not better outcomes. No positive cost means no usable return ratio.

Only dates and org narrow this comparison. It intersects held activity/credit date spans; that does not prove every day loaded. Org-unfilterable costs are omitted. Missing credits can inflate headline return. Check included costs and the per-line pairing, not the ratio alone.

The headline value excludes free unlicensed chat but can still include activity whose credit cost is unavailable. Azure/Foundry and GitHub Copilot are outside this comparison. Metric explainer / Consumption

Credits are quantities.
Cost adds pricing rules.

The same number of credits can produce a different cost.

Prepaid credits = min(credits used, pack balance)
Cost = prepaid credits x prepaid rate
+ remaining credits x pay-as-you-go rate

Illustrative Cowork example / not actual usage or contract rates

Cowork draws down the selected period's pack balance in date order. Later weeks spill into PAYG first. Unused pack balance is not added as a cost here. Blended rate = calculated cost / credits used.

Metric explainer / Consumption

Reading budget runway
and source scope

Illustrative example / $100 spent through day 10 of a 30-day month

Daily average = $100 / 10 = $10/day
Projected month end = $10 x 30 = $300
With a $250 budget: at risk; crossing is around day 25.

Elapsed days end at the newest source date. Under three days: too early. At/above budget: over. Projection above budget: at risk; otherwise on track. No positive budget: no comparison.

Cowork spreads weekly cost evenly across seven days. A $70 week split three days / four days between months contributes $30 / $40. This is allocated, not measured daily spend.

Metric explainer / Efficiency

Fit grades
and their denominators

At Balanced: Strong fit spans two or more recognised apps, builds/packages a file, or has 3+ material items of 2+ kinds (or more than 5 items). Fair fit has some sources, reads messages or stays in one app. Chat with nothing attached is Worth a look; insufficient evidence is ungraded.

Frontier includes Opus / GPT-6; Workhorse includes Sonnet, other Claude, GPT-5 / GPT-4. The thread takes its dearest logged tier. Model verdict shares divide by judged threads; logged share divides threads with a tier by all model threads. A segment needs five judged threads for a verdict.

The fit/model cards count distinct thread IDs; do not assume they equal Adoption's user + app + thread sessions. Cowork fit's Tasks completed card counts distinct prompts, not verified completions.

Higher strong-fit share means more recorded complex work, not better outputs. Lower model match is a test candidate, not proven wasted spend: no per-call token cost is held. Metric explainer / Readiness

How licence
priority is scored

For each unlicensed candidate, T is tasks per active week and D is active days per active week. Each is total recorded activity / distinct weeks with unlicensed prompts, not all elapsed calendar weeks. The measures called Median take a median across people, not across weekly values for one person.

Without matched Microsoft 365 breadth:
score = round(60 x min(T/30, 1) + 40 x min(D/5, 1))
With breadth B (workloads per active M365 day):
round(50 x min(T/30, 1) + 30 x min(D/5, 1)
+ 20 x min(B/4, 1))

Illustrative example / T = 15 tasks, D = 4 days, B = 2 workloads

Each component caps at 1 before weighting. No positive tasks/days means no score; the candidate list also needs an observed unlicensed session. No matched breadth keeps the 60/40 formula, rather than deducting 20 points.

Read the other figures alongside it

Active unlicensed users is a count; share divides by all active users. Sessions per person/week is not the task count used to score. More resources per prompt can increase tasks without proving more demand.

Dormant seats use 30+ days inactive before the newest audit date; reclaim value is dormant seats x Monthly Licence Cost. Zero configured cost means not costed. These estate cards ignore date and org filters, while demand and candidates follow them.

A score of 62 is not a 62% chance of value. Few active weeks, a stale/mismatched licence snapshot, concealed names or incomplete source coverage weaken it. Trial with willing users and assess outcomes before allocating or reclaiming seats.

Task intensity and breadth are evidence of use, not proven incremental benefit
